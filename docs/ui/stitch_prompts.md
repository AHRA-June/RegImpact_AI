# Stitch UI 프롬프트 — RegImpact AI

> Google Stitch(AI UI 디자인)에 붙여넣을 프롬프트 모음.
> 원칙: **챗봇 아님. 검증 가능한 의사결정 지원 콘솔**(금융 리스크/컴플라이언스 툴 톤).
> UI 라벨은 한국어. 데이터는 6·30 메인 시나리오 실제값 사용(진짜처럼 보이게).
>
> 사용법: ① 먼저 "0. 마스터 컨텍스트"를 붙여 앱/디자인 시스템을 잡고 → ② 각 화면 프롬프트를 하나씩 생성 → ③ 필요 시 "리파인" 지시로 다듬기.
>
> ⚠️ 구현은 Streamlit 수준으로 가볍게 유지(브리프 §21). Stitch 산출물은 **포트폴리오/README/면접용 목업 + 구현 참고 디자인**.

## 0. 마스터 컨텍스트 (매 화면 앞에 붙이거나 첫 지시로)

```
프로덕트: "RegImpact AI" — 생성형 AI 기반 주택담보대출 규제 변경 영향분석·검증 시스템.
사용자: 금융회사 여신정책 담당자, 모델리스크관리/모델검증, AI Governance 담당자.
목적: 정부의 가계대출 규제가 바뀌면, 담당자가 공식 공문을 업로드하고 → AI가 여신 Rule·
고객 영향·테스트케이스에 대한 영향분석 '초안'을 만들고 → 그 결과의 정확성을 검증(Assurance)해 →
사람이 검토·승인하는 의사결정 지원 도구. 챗봇 아님. 검증 가능성과 추적성이 핵심.

디자인 언어:
- 엔터프라이즈 핀테크 / 규제·컴플라이언스 콘솔 톤. 차분하고 신뢰감 있게. 데이터 밀도는 높되 매우 가독성 높게.
- 마케팅용 히어로 섹션·화려한 그래픽 금지. 리스크관리 대시보드처럼.
- 라이트 테마 기본(다크 옵션 지원). 배경 아주 연한 회색(#F7F8FA), 카드 흰색, 테두리 #E5E7EB, 본문 텍스트 #1A1A2E.
- 액센트: 신뢰감 있는 딥 네이비/인디고(#1E3A5F). 상태 색 — 승인/통과 초록(#1E8E5A), 검토필요/경고 앰버(#B7791F), 실패/고위험 레드(#B42318), 정보 블루(#2563EB).
- 문서 ID·해시·정책ID·인용은 모노스페이스 폰트. 한글 본문은 Pretendard/Noto Sans KR 계열.
- 반복 요소: 좌측 사이드 내비, 상단 앱바(시나리오 선택 + 승인상태), 상태 뱃지, 근거(evidence) 인용 칩, Phase 타임라인 표식, 감사추적 패널.

좌측 사이드 내비 항목(공통):
개요 · 규제 변경 분석 · 임팩트 매트릭스 · Rule 변경안 · 검증(Assurance) · 고객·포트폴리오 영향 · 감사추적

상단 앱바(공통):
좌: "RegImpact AI" 로고 텍스트 + 시나리오 드롭다운("2026-06-30 규제지역 추가 지정")
우: 전체 승인상태 뱃지("검토 필요"), 사용자 아바타.

플랫폼: 반응형 웹 대시보드(데스크톱 우선).
```

## 1. 규제 변경 분석 워크스페이스 (메인) — ⭐제품의 얼굴

```
화면: "규제 변경 분석" 메인 워크스페이스. 3분할 레이아웃.

[좌측 패널 — 소스/공문]
- 제목 "공식 원문 (Source Snapshot)"
- 업로드된 문서 카드 3개(각각 아이콘+제목+메타):
  · "금융위 보도참고자료" — 기관: 금융위원회 · 발표 2026-06-30 · source_hash: 403fb8fb… (모노스페이스, 축약)
  · "국토부 보도참고자료" — 국토교통부 · 2026-06-30 · 6115271b…
  · "규제지역 추가 지정 관련 FAQ" — 관계기관 합동 · 2026-06-30 · ef3dad7b…
- 하단 "공문 업로드" 점선 드롭존 버튼.

[중앙 패널 — Before/After 변경 요약]
- 상단 카드 "핵심 변경(Before → After)":
  · 규제지역 주담대 LTV: 70% → 40% (무주택 기준)  ← 큰 숫자, 화살표 강조
  · 시행일: 2026-07-01 (발표 다음날)  · 배지 "D-1 발표"
  · 대상지역 칩: 화성 동탄 · 용인 기흥 · 구리
  · 예외 칩: 생애최초 70% · 서민·실수요자 60%
  · 경과규정: 2026-06-30까지 접수/계약+계약금 → 종전규정
- 각 항목 옆에 작은 "근거" 인용 칩(클릭하면 원문 스팬으로 이동하는 느낌). 인용 칩엔 "FAQ Q2", "FSC p2" 같은 출처 라벨.

[우측 패널 — 처리 파이프라인 상태]
- 세로 스텝 리스트(각 단계 체크/진행 아이콘):
  원문 스냅샷 ✓ → 정책버전 해석 ✓ → Before/After 추출 ✓ → 임팩트 매트릭스 ✓ →
  Rule 변경안 ✓ → 테스트케이스 ✓ → Rule 회귀검증 ✓ → Assurance 평가 ⚠ → 사람 검토 ○
- 하단 "검증(Assurance) 결과 보기" 강조 버튼.

전체 톤: 신뢰감, 추적성. 모든 수치 옆에 근거 인용이 보이는 게 핵심.
```

## 2. 임팩트 매트릭스 — ⭐핵심 차별점(시간축 Phase)

```
화면: "임팩트 매트릭스" — 규제 변경이 업무 전반에 미치는 영향을 한 표로.
상단에 Phase 타임라인 탭/범례: [D-day 전(시행 전 필수)] · [시행 후] · [별도 트리거]

메인은 큰 데이터 테이블. 열:
업무영역 | 변경 내용 | 근거(evidence) | 영향 대상 | 산출물 | 우선순위 | 기한(Phase) | 담당 | 승인상태 | 자동처리

행(예시 데이터):
1) 변경사항 식별·규정 해석 | LTV 70→40%, 시행 7.1 | [FAQ Q2] | 규제지역 신규대출 | 변경요약 | 필수 | D-day 전 | 정책 | 검토필요 | 자동
2) 고객·포트폴리오 영향 | 규제지역 무주택 한도 축소 | [FSC p2] | 영향 고객 1,240명 | 영향분석 | 필수 | D-day 전 | 정책 | 검토필요 | 자동

4) 전산 요건 | 지역코드 매핑·LTV 변수 수정 | [FSC] | 대출 전산 | IT 요청서 초안 | 필수 | D-day 전 | IT | 초안 | 반자동

6) 경과규정 처리 | 6.30까지 접수/계약 종전규정 | [FAQ 참고표] | 기존 신청건 | 판정기준 | 필수 | D-day 전 | 정책 | 검토필요 | 자동
```

## 3. Rule 변경안 + 사람 검토 — 거버넌스 화면

```
화면: "Rule 변경안 (Rule Change Proposal)" — LLM이 제안한 구조화된 변경안을 사람이 승인.
상단 배너(중요): "LLM은 실행 코드를 직접 수정하지 않습니다. 구조화된 변경안만 제안하고, 사람 승인 후
deterministic rule registry에 반영됩니다." (신뢰 강조, 연한 인디고 배경)

[좌: Before/After 구조화 diff — 나란히 비교]
rule_id: MORTGAGE_LTV_REGULATED_REGION
change_type: MODIFY
Before                          After
- region_status: NON_REGULATED  region_status: REGULATED
- max_ltv: 0.70                 max_ltv: 0.40          ← 변경 라인 하이라이트
                                target_regions: [GURI, YONGIN_GIHEUNG, HWASEONG_DONGTAN]
                                effective_from: 2026-07-01
exceptions: [FIRST_HOME_BUYER(0.70), REAL_DEMAND(0.60)]
grandfathering: cutoff 2026-06-30 / [ACCEPTED, CONTRACT+DOWNPAYMENT]
- 변경/추가 라인은 diff 색(추가 초록, 변경 앰버). 우측에 근거 인용 칩 "FAQ Q2".

[우: 사람 검토/승인 카드]
- 승인 상태 스텝퍼: DRAFT → REVIEW_REQUIRED(현재, 앰버 강조) → APPROVED → 반영
- 검토자, 코멘트 입력창
- 버튼: [승인] [반려] [사람에게 에스컬레이션]
- 하단 "이 변경안이 escalate된 이유": "경과규정 이벤트 해석 확인 필요" 태그.

전체: 감사 가능성. 누가/언제/어떤 근거로 판정했는지 보이게.
```

## 4. 검증(Assurance) 대시보드 — ⭐신뢰의 기반(A)

```
화면: "검증(Assurance)" — AI 결과가 틀리지 않았는지 정량 검증 결과.
상단 요약 배지 줄: 전체 판정 "검토 필요" / LOCKED TEST 기준.

[상단 — 핵심 지표 카드 4개(큰 숫자 + 통과/실패 색 + 임계값)]
- Citation Correctness: 98% (임계 ≥95%, 초록 통과)
- Exception Recall: 100% (임계 100%, 초록)  ← 생애최초·서민실수요 누락 0
- Grandfathering Recall: 92% (임계 ≥95%, 앰버 경고)
- Rule-regression Pass Rate: 100% (24/24, 초록)

[중단 — 할루시네이션 계열 2개]
- Unsupported Claim Rate: 1.2% (낮을수록 좋음, 초록)
- Source Contradiction Rate: 0% (초록)

[하단 — 검증 체크 리스트(항목 + 상태 아이콘)]
Source grounding ✓ · Change completeness ✓ · Exception detection ✓ ·
Temporal/정책버전 일관성 ✓ · Rule conflict ✓ · Human escalation 평가 ⚠(1건) · Audit trail ✓
- 각 항목 클릭 시 근거/실패 케이스로 이동.

[우측 사이드 — Escalation 요약]
- "사람 검토 필요 1건": 경과규정 이벤트 해석 모호 → 카드로 표시, "검토로 이동" 링크.

주의: 이 화면은 '정확도 자랑'이 아니라 '실패를 어떻게 통제하는가'를 보여주는 톤.
그래서 앰버/경고도 숨기지 않고 정직하게 노출.
```

## 5. 고객·포트폴리오 영향 (선택/스트레치)

```
화면: "고객·포트폴리오 영향" — 합성 포트폴리오 기준 영향 시뮬레이션.
상단 배지: "synthetic portfolio 결과 (실데이터 아님)"  ← 정직성 표기 필수.

[상단 스탯 타일 4개]
- 영향 고객: 1,240명 · 경과규정 대상: 312명 · 평균 한도 감소: -1.8억 · 고위험(0% 적용): 87명

[중단 차트 2개 — 단순하게]
- 막대: 차주 유형별 영향(무주택 일반 / 생애최초 / 서민실수요 / 유주택 / 다주택)
- Before/After LTV 분포(그룹 막대: 70% 구간 → 40%/0% 이동)

[하단 테이블] 영향 고객 세그먼트: 지역 · 차주유형 · 기존 LTV · 변경 LTV · 경과규정 · 판정근거(reason_code 칩)
색 규칙: 0% 적용은 레드, 경과규정 종전유지는 초록.
```

## 리파인 팁 (Stitch에 추가 지시할 때)
- "데이터 밀도를 더 높이고 여백을 줄여줘 — 규제 콘솔 느낌."
- "모든 수치 옆에 근거 인용 칩을 넣어줘(추적성)."
- "상태는 색 뱃지로, 초록/앰버/레드 일관되게."
- "히어로/마케팅 요소 빼고, 리스크관리 툴처럼 진지하게."
- "다크 모드 버전도 만들어줘."
- 한글 라벨 유지: "화면 텍스트는 한국어로."
