# 기능단위·PRD 버전 관리 규칙 (STANDARD)

> **이 문서는 PRD와 기능단위(feature-unit) 문서를 버전별로 관리하는 표준이다.**
> 확정일: 2026-08-13. 이후 모든 PRD·기능단위 문서 작성/수정은 이 규칙을 따른다.
> (룰 명세 LOCKED §4·상태판 규칙과 별개의, 문서 형상관리 규칙이다.)

---

## 왜 버전별로 관리하나
- 이 프로젝트는 **개발 도중 Claude 계정이 교체**된다(대화 메모리 의존 금지).
- 포트폴리오 용도상 "무엇이 어떻게 진화했는가"를 **저장소 안에서 눈으로** 보여야 한다.
- git 히스토리와 별개로, 각 기능의 **의사결정 스냅샷**을 문서로 남긴다.

## 3대 원칙
1. **새 파일 = 전체 스냅샷.** 수정·업데이트가 있으면 파일을 **덮어쓰지 않고** 새 버전 파일을 만든다.
   이전 버전 파일은 **절대 삭제·수정하지 않는다**(그 시점의 진실로 보존).
2. **변경 이력은 두 곳에.** 새 버전 파일 **상단**에 "이전 버전 대비 변경"을 적고,
   폴더 **`CHANGELOG.md`**에 누적 이력을 쌓는다(최신이 위).
3. **수정된 것은 모두 적는다.** before→after를 항목별로. "어디를, 무엇에서 무엇으로, 왜" 3요소.

## 네이밍 (시맨틱 vN)
```
docs/features/<feature-slug>/
├── CHANGELOG.md                 # 이 기능의 버전 누적 이력 (최신이 위)
├── <feature-slug>_v1.md         # v1 스냅샷 (보존)
├── <feature-slug>_v2.md         # v2 스냅샷 (보존) ← 수정 시 새로 생성
└── ...
```
- `vN`: 1부터 정수 증가. 변경의 크기와 무관하게 **업데이트 1회 = +1**.
- **최신 버전 = 가장 큰 N.** 폴더의 `CHANGELOG.md` 맨 위 항목이 현재 유효 버전을 가리킨다.
- PRD도 동일: `docs/prd/<prd-slug>/<prd-slug>_vN.md` + `CHANGELOG.md`.

## 새 버전 파일 상단 필수 블록
모든 `_vN.md`는 본문 앞에 아래 블록을 둔다.
```markdown
> **버전:** vN   **날짜:** YYYY-MM-DD   **상태:** (초안/유효/폐기)
> **이전 버전:** v(N-1) (또는 "없음 — 최초 작성")

## 변경 이력 (v(N-1) → vN)
- **[분류]** <항목>: `이전값/이전서술` → `새값/새서술` — 이유.
- ...
(최초 작성이면: "- 최초 작성 (신규). 이전 버전 없음.")
```
분류 태그 예: `[값]` `[로직]` `[인터페이스]` `[문서]` `[범위]` `[버그]` `[제약]`.

## 본문 권장 목차 (기능단위)
1. 목적·책임 (한 줄 정의 + 왜 필요한가)
2. 입력/출력 인터페이스 (스키마·시그니처)
3. 핵심 로직·설계 결정 (why)
4. 관련 파일 (src / tests / examples / docs)
5. 검증 상태 (테스트 수·지표)
6. 알려진 제약·모호성 (OPEN_QUESTIONS 연결)

---

## 워크플로우 (수정이 생겼을 때)
1. 현재 최신 `<slug>_vN.md`를 복사해 `<slug>_v(N+1).md` 생성.
2. 상단 블록 갱신: 버전/날짜/이전버전, **변경 이력(before→after) 모두** 기입.
3. 본문 수정.
4. 폴더 `CHANGELOG.md` 맨 위에 `## vN+1 (YYYY-MM-DD)` 항목 추가(요약 + 변경 목록).
5. 이전 버전 파일은 손대지 않는다.
6. `docs/01_PROJECT_STATE.md` 작업 로그에 반영.

> 원칙: **삭제 없음, 덮어쓰기 없음, 이력 누락 없음.**
