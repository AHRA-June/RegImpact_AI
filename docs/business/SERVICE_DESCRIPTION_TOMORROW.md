# 내 한도 시그널 — 서비스 설명서

**팀 엣지케이스 (EdgeCase)** · 서비스 유형: 웹 (금융앱 웹뷰 탑재형)
동작 데모: **https://ahra-june.github.io/RegImpact_AI/signal.html**

---

## 1. 한 줄로

> **규제가 바뀐 다음 날, 내 대출 한도가 얼마에서 얼마로 달라졌고, 나는 경과규정 대상인지,
> 그리고 무엇에 막혀 있는지를 — 근거 조문과 함께 알려주는 개인화 시뮬레이터.**

---

## 2. 왜 이 서비스인가

2026년 6월 30일 저녁, 규제지역이 추가 지정됐습니다. 시행은 **다음 날**입니다.

뉴스는 "LTV 70% → 40%"라고만 말합니다. 그러나 실제로는 생애최초 구입자는 70%가 그대로고,
서민·실수요자는 60%, 이미 집이 있으면 0%입니다. 계약금을 낸 사람은 종전 규정을 유지합니다.
**같은 날 같은 아파트를 계약한 두 사람의 한도가 2억 4천만 원 차이 납니다** — 차이는 계약금
영수증 한 장입니다.

고객은 두 방향으로 틀립니다. 경과규정 대상인데 겁먹고 계약을 포기하거나, 대상이 아닌데
안심하고 있다가 잔금일에 막힙니다. 그 혼란은 전부 창구와 콜센터로 밀려옵니다.

기존 도구로는 이 질문에 답할 수 없습니다.

- **한도 계산기**(토스·핀다 등)는 '오늘의 규칙' 하나만 압니다. 변경 전/후 비교도, 경과규정
  판정도, 근거 제시도 없습니다. 위의 두 사람에게 **같은 숫자**를 보여줍니다.
- **AI 규제 모니터링**은 공문을 요약해 알리는 데서 끝납니다. "그래서 내 한도는?"이라는
  개인화 판정이 없습니다.

그 사이의 비어 있는 층 — **변경 → 개인화 판정 → 근거 → 검증** — 이 저희 자리입니다.

## 3. 무엇을 하는가

고객이 앱에서 조건 몇 가지(지역·주택 보유·주택 가격·계약 일자·소득)를 넣으면, 다음 다섯
가지가 한 화면에서 이어집니다.

### ① 영향 알림
공문 발표 시 고객 조건 기준으로 "나에게 영향 있음/없음"을 알립니다. 신규 지정 지역과
시행일이 함께 표시됩니다.

### ② 변경 전 → 후, 내 한도
같은 조건을 **시행 전·후 두 시점으로 각각 판정**해 나란히 보여줍니다.
예: 구리시 8억 아파트·무주택 → **변경 전 LTV 70% / 5억 6천만 원 → 변경 후 40% / 3억 2천만 원
(약 2억 4천만 원 감소)**. 값만이 아니라 **어느 규칙에서 그 결론이 났는지 판정 경로**도 펼쳐
볼 수 있습니다.

### ③ 경과규정 체크
계약 체결일·계약금 납부 여부·대출 신청 접수일을 넣으면 종전 규정 적용 가능성을 판정하고,
해당하면 **"종전 기준 유지"** 배지와 함께 근거 조문("규제지역 효력 발생일 전일까지 …
종전 규정이 그대로 적용된다")을 보여줍니다. 준비할 증빙도 안내합니다.

### ④ 총 가능금액 — 어느 규제에 막혔는지까지
*(고객 인터뷰 반영 기능)*

한도는 LTV 하나로 정해지지 않습니다. 실제 심사는 **min(LTV 한도, 가격구간별 최대한도,
DSR 한도, DTI 한도)** 입니다. 연소득·기존 대출 월 상환액·금리·만기·기관(은행/2금융)을 넣으면
네 한도를 **나란히 막대로** 보여주고, 가장 낮은 한도에 **"← 여기에 막혀요"** 를 표시합니다.

> 실제 화면 예: 연소득 5,000만 원·기존 월 상환 100만 원·금리 4% →
> LTV 3억 2천 · 최대한도 6억 · **DSR 1억 4천 · DTI 1억 4천** → **"DSR·DTI에 막혀요"**
> 2금융권으로 바꾸면 DSR만 완화되고 DTI가 홀로 병목으로 남습니다.

"당신의 한도는 1억 4천만 원이고, **LTV가 아니라 DSR 때문**입니다"라고 말해주는 계산기는
현재 없습니다. 고객이 다음에 무엇을 해야 하는지(부채 정리인지, 지역 조정인지)가 여기서
갈립니다.

### ⑤ 근거 우선 Q&A
"잔금일이 시행일 뒤인데 저는 어떻게 되나요" 같은 자연어 질문에, 검수된 쉬운 안내를 먼저
보여주고 **공문 원문 문단**을 함께 답니다. 원문은 줄바꿈과 쪽 구분까지 그대로 열람할 수
있고, 해당 문장은 음영으로 짚어줍니다. **근거를 찾지 못하면 지어내지 않고** 원문 전체
열람과 전문 상담을 안내합니다.

## 4. 무엇이 다른가 — 계산기는 '상태'에, 시그널은 '사건'에 답한다

|  | 일반 한도 계산기 | 내 한도 시그널 |
|---|---|---|
| 답하는 질문 | 지금 얼마 빌릴 수 있나 — **오늘의 상태** | 규제가 바뀌면 나는 뭐가 달라지나 — **변경이라는 사건** |
| 시점 | 현재 규칙 하나 | 변경 전/후 두 시점 비교 + 경과규정·생애최초 등 **경계 조건 판정** |
| 한도 근거 | LTV 중심의 단일 숫자 | LTV·최대한도·DSR·DTI를 합산하고 **병목 규제를 지목** |
| 답의 근거 | 숫자만 (출처 없음) | 공문 원문 인용 — 인용이 원문에 실재하는지 **기계 대조** |
| 틀렸을 때 | "단순 참고용" 고지 | 독립 오라클 대조·회귀 테스트·감사로그가 **배포 조건** |

규제 사고는 평균값이 아니라 **가장자리(edge case)** 에서 납니다. 경과규정 하루 차이, 생애최초
예외, 유주택 0%, DSR 병목 — 팀명이 엣지케이스인 이유입니다.

**모방 가능성에 대해:** 화면은 베낄 수 있습니다. 그러나 판정의 재료인 확정 룰 명세, 골드
평가셋, 독립 재구현 오라클은 여신 실무에서 손수 쌓아야 하는 검증 자산이고, 이것 없이는
금융회사가 자기 이름으로 "고객님은 경과규정 대상입니다"라고 말할 수 없습니다. 핀테크는
"참고용"이라 쓰고 넘어갈 수 있지만, 은행 공식 앱은 그럴 수 없습니다. **그 간극이 저희
자리입니다.**

## 5. 왜 믿을 수 있나 — AI가 판정하지 않는 AI 서비스

한도 안내가 틀리면 그건 오답이 아니라 **금융사고**입니다. 그래서 역할을 갈랐습니다.

- **LLM은 공문에서 사실만 추출합니다.** 모든 항목에 원문 인용이 강제되고, 인용이 원문에
  실제로 존재하는지 기계가 글자 단위로 대조합니다. → 실측 **인용 정확성 75/75 (100%)**
- **판정은 사람이 확정한 명세를 구현한 결정적 룰엔진이 합니다.** LLM은 규칙 값을 만들지
  않습니다. 화면의 모든 비율·날짜는 엔진 상수에서 나오며, 화면에 엔진이 모르는 값이 있으면
  테스트가 실패합니다.
- **엔진은 독립 재구현 오라클과 대조됩니다.** 명세에서 따로 유도한 검증기와 전 케이스를
  맞춰봅니다. → **36/36 (100%)**
- **브라우저에서 도는 판정 엔진은 원본과 자동 대조 후에만 배포됩니다.** →
  **판정 36건 + 지역×시점 조회 450건 + 한도 계산 150건 = 636건 전건 일치.** 하나라도
  어긋나면 배포가 중단됩니다.
- **산출 과정은 해시체인 감사로그**로 남아 사후 변조를 탐지할 수 있습니다.
- 전체 자동 테스트 **563개**가 매 배포마다 통과해야 합니다.

**검증 성적표를 함께 공개합니다.** 12개 지표를 확정 임계와 대조해 **11개 통과 · 미달 0 ·
미측정 1**로 보고하며, **미측정을 통과로 세지 않습니다**. 모르는 것을 통과로 처리하는 것이
검증 체계가 무력해지는 가장 흔한 경로이기 때문입니다.

Q&A(RAG)도 같은 원칙입니다. 검색 품질을 **원문 대조를 통과한 정답 인용 기준으로 실측**하며
(recall@5 **82%**, 못 찾은 인용도 화면에 함께 표기), 답변의 인용은 원문과 대조합니다. 근거가
없으면 답하지 않습니다. (평가셋 115문항은 현재 사람 검수 진행 중이며, 확정 전까지 이 수치는
절대 성능이 아니라 개선 비교용으로 씁니다 — 이 구분 자체를 문서와 화면에 표기합니다.)

## 6. 고객과 현업, 같은 엔진으로 동시에

이 엔진은 고객 화면 전용이 아닙니다. **같은 엔진이 현업(심사·리스크)용 산출물을 이미
구동하며, 전부 공개 운영 중입니다.**

| 현업 산출물 | 무엇인가 | 실측 |
|---|---|---|
| 규제 변경 추출·검증 | 공문에서 변경 항목을 구조화하고 인용을 원문 대조 | 변경 75건 · 인용 100% |
| 임팩트 매트릭스 | 업무영역별 조치·기한·담당. 자동처리 불가 행은 **사유 없이 생성 불가** | 30행 · 자동처리 67% |
| 포트폴리오 영향 분석 | 보유 신청 건을 시행 전·후 두 시점으로 전량 재평가 | 2,000건 중 **638건(31.9%) 한도 감소 · 총 −1,549억 원 · 경과규정 보호 134건** |
| 룰 변경안 + 회귀 테스트 | 심사 룰 개정안과 테스트케이스 자동 생성·검증 | 36케이스 100% |
| 검증보고서·모델카드·리스크 레지스터 | 감독 대응·내부 증빙에 쓰는 문서, 같은 실행에서 자동 생성 | 리스크 18건/5범주 |

즉 **하나의 검증된 엔진으로 B2C 콘텐츠와 B2B 내부 도구를 동시에 서비스**합니다.
고객이 보는 답과 창구·심사가 보는 근거가 같은 엔진에서 나오므로, 규제 발표일 응대의
일관성이 구조적으로 확보됩니다.

## 7. 슈퍼SOL 연계 기대효과

1. **규제 발표일의 경험 차별화** — 다른 앱은 뉴스를 주고, 슈퍼SOL은 '내 답'을 줍니다.
   고객 불안이 최고조인 시점에 개인화된 답변을 제공하는 첫 금융앱이 됩니다.
2. **상담 부담 분산** — 발표 직후 창구·콜센터로 몰리는 "저는 어떻게 되나요"를 앱 내
   자가확인으로 흡수합니다.
3. **주담대 퍼널 상단 선점** — 한도가 궁금한 순간이 대출 여정의 시작점입니다. 시뮬레이터
   에서 상담·한도조회로 자연스럽게 이어집니다. 기존 한도조회를 대체하지 않고 **앞단**에서
   증폭합니다.
4. **신뢰 브랜딩** — 근거 조문 인용과 검증 체계에 기반한 AI 안내는 금융 AI 설명책임
   흐름과 정합하며, '믿을 수 있는 AI'를 슈퍼SOL의 자산으로 만듭니다.
5. **현업 확장성** — 같은 엔진이 심사·리스크 현업 도구로 확장되므로, 한 번의 온보딩으로
   고객 콘텐츠와 내부 업무도구가 함께 열립니다.

기술적으로도 부담이 적습니다. 판정 엔진이 브라우저에서 동작하므로 **웹뷰 하나로 탑재**되고,
**서버 호출이 없어 고객 입력이 외부로 나가지 않습니다.**

## 8. 지금 되는 것과, PoC 기간에 할 것

과장하지 않기 위해 구현 상태를 구분해 밝힙니다.

**이미 동작합니다 (공개 데모에서 직접 확인 가능)**
- 변경 전/후 판정·경과규정·예외 판정 엔진, 브라우저 실행 + 원본 대조 636건
- 총 가능금액 계산기(LTV·최대한도·DSR·DTI + 병목 표시)
- 근거 조문 인용·원문 전체 열람·문장 강조
- 공문 원문 검색(BM25, 한국어 토크나이저) 및 recall 실측
- 현업 산출물 전체(추출 검증·임팩트 매트릭스·포트폴리오 영향·검증보고서·모델카드)

**PoC 기간 목표**
- 자유 질문에 문장으로 답하는 LLM 연결 (모든 문장에 인용 부착, 근거 없으면 상담 안내)
- 실시간 공문 수집·추출 파이프라인 자동화
- 슈퍼SOL 웹뷰 연동 및 사용성 테스트

**현재의 한계 (그대로 밝힙니다)**
- LTV·DSR·DTI 참고 추정이며 **스트레스 금리 가산은 미반영** — 실제 한도는 이보다 적을 수
  있고, 최종 가능 금액은 은행 심사로 확정됩니다.
- 포트폴리오 영향 수치는 합성 데이터 기반이며 실 고객 데이터를 사용하지 않았습니다.
- 원문에 기준값이 없는 구간(예: 일부 유주택 조건)은 **추정하지 않고 사람 검토로 넘깁니다.**
  자동 판정 커버리지 91.4%, 영향 측정 74.1%가 100%가 아닌 이유가 이것이며, 값을 지어내면
  즉시 100%가 됩니다. **그 자리를 비워 두는 것이 이 서비스의 설계 원칙입니다.**

## 9. PoC 계획

6·30 규제 시나리오 시뮬레이터를 슈퍼SOL 웹뷰 콘텐츠로 전시합니다.

- **평가 지표:** 완주율, 결과 이해도 응답, 상담·한도조회 전환율, 발표일 인입 상담 변화
- **라이브 대응:** 전시 기간 중 실제 규제 이벤트 발생 시 즉시 반영(규제 변경은 반복
  이벤트입니다 — 2026년에만 3건)
