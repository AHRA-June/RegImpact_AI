## Q9. 비규제지역 **유주택** LTV — 원문 60%를 채택할 것인가 — `[대기, 도메인 확인 필요]`
- **발견 경위:** 전국 지역 레지스트리 도입(2026-08-18) 후 울산·제주 등 실제 비규제 지역이 선택 가능해지면서,
  비규제 유주택 경로가 처음으로 실제 시나리오가 됐다. 현재는 전부 `NEEDS_HUMAN_REVIEW`.
- **원문:** MOLIT 보도자료 참고1 — `"非규제지역(수도권 外) 무주택(처분조건부 1주택) 70% / 유주택 60%"`
- **현재 명세:** `05_RULE_SPEC §C-2`는 무주택 70%만 확정하고, "非규제 수도권 外 유주택 60%는 다른 맥락이니
  혼동 금지"라고 **명시적으로 유보**했다. LOCKED §4에 따라 임의 채택하지 않음.
- **사용자 판단 필요:**
  ① 비수도권 비규제 유주택 = **60%** 로 확정할 것인가 (원문 그대로)
  ② 수도권 비규제(인천·경기 대부분) 유주택은? 원문에 서술 없음 → escalation 유지인가
  ③ ①을 채택하면 `capital_area` 플래그가 판정 분기 조건이 된다(레지스트리에 이미 준비됨).
- 회귀 케이스 `CFL-07`이 현재 동작(escalation)을 고정하고 `spec_note`로 이 모호성을 표면화한다.

## Q10. 비규제 **수도권 다주택** — §C-1b(R6) vs §H 상충 — `[대기, 도메인 확인 필요]`
- **발견 경위:** Q9와 동일. 인천 연수구 같은 수도권 비규제 지역이 선택 가능해지며 도달 가능한 경로가 됐다.
- **원문:** FSC 보도자료 p2 — `"다주택자는 수도권 內 주택구입시 규제지역 여부와 무관하게 LTV 0% 적용"` (C06)
- **상충:**
  - `§C-1b` R6: "다주택 · **수도권(규제 무관)** 0%" → 비규제 수도권도 0%
  - `§H` 의사코드(**엔진 구현의 기준**): P3(다주택)이 P2 지역분기 **뒤**에 있어 비규제 경로에서는 도달하지 못함
    → 현재 결과는 `OWNER_BASELINE_UNKNOWN` escalation
- **현재 채택(잠정):** §H가 권위 기준이므로 escalation. 회귀 케이스 `CFL-06`으로 고정 + `spec_note` 표면화.
- **사용자 판단 필요:** §H의 P3를 지역분기 **앞**으로 올려 "수도권 다주택 0%"를 선(先)판정할지,
  아니면 현행대로 둘지. 전자를 택하면 §H·엔진·오라클·회귀를 함께 갱신한다.

## Q8. 명세 내부 상충: 유주택 + 생애최초 처리 — `[대기, 도메인 확인 필요]`
- **발견 경위:** TC Generator 충돌 케이스(CFL-04) 작성 중 `05_RULE_SPEC` 내부 두 서술이 상충함을 확인.
  - `§E` 주석: "유주택 AND 생애최초 = 논리상 불가(생애최초=세대원 전원 무주택 이력). **데이터 충돌 시 → `NEEDS_HUMAN_REVIEW`.**"
  - `§H` 의사코드("엔진 구현의 기준"): P4(유주택 비처분)에서 **0%로 short-circuit** → P5(생애최초)에 도달하지 않음.
- **현재 채택(잠정):** `§H`가 "엔진 구현의 기준"으로 명시되어 있으므로 **0%(§H)** 를 권위 기준으로 두고,
  룰엔진·오라클·회귀 모두 0%로 일치. CFL-04 케이스에 `spec_note`로 이 모호성을 표면화.
- **사용자 판단 필요:** 실제 운영에서 house_count≥1 & first_home_buyer=True 라는 **모순 입력**이 들어오면
  ①§H대로 0% 자동판정할지, ②§E대로 데이터 무결성 오류로 보고 `NEEDS_HUMAN_REVIEW`로 escalate할지.
  후자를 택하면 엔진에 "입력 모순 감지 → escalation" 분기를 추가하고 오라클·회귀도 함께 갱신.
