## Q9. 비규제지역 **유주택** LTV — `[✅ 해결 2026-08-18]`
- **결정: 60% 확정.** 근거 = MOLIT 참고1 `"非규제지역(수도권 外) 무주택(처분조건부 1주택) 70% / 유주택 60%"`.
- **적용 범위:** 원문이 **"수도권 外"** 를 명시하므로 **비수도권 비규제**에만 적용한다.
  **수도권 비규제(인천·경기 대부분) 유주택은 근거 부재** → `OWNER_BASELINE_UNKNOWN` escalation 유지.
  (사용자 확정은 "60% 확정"이었고, 수도권 처리는 Q9 제기 시 제시한 기본값 = escalation 유지를 채택.
   수도권도 60%로 통일하려면 `rule_engine._decide_by_region` P4의 `capital_area` 분기 한 줄이면 된다.)
- **다주택과의 관계:** 비수도권 비규제 다주택은 Q10의 0% 대상이 아니므로 **유주택 기준 60%** 로 수렴.
- 반영: `05_RULE_SPEC §C-2·§H`, `rule_engine.LTV_NONREG_OWNER`, reason_code `LTV_NONREG_OWNER_60`,
  rule_id `NONREG_OWNER_60`. 회귀 `OWN-01~05`, `CFL-07`, `CFL-08`.

## Q10. 비규제 **수도권 다주택** — `[✅ 해결 2026-08-18]`
- **결정: P3(다주택)을 지역 분기 앞으로 이동.** 근거 = FSC p2 `"다주택자는 수도권 內 주택구입시 규제지역
  여부와 무관하게 LTV 0% 적용"` (C06) + `§C-1b R6`.
- **조건:** 다주택 AND (규제지역 OR 수도권) → 0%. 비수도권 비규제 다주택은 Q9의 유주택 기준 60%.
- 종전 §H는 P3가 P2 지역분기 뒤에 있어 비규제 경로에서 도달 불가였다. 전국 지역 레지스트리 도입으로
  도달 가능해지며 드러난 상충이다.
- 반영: `05_RULE_SPEC §C-2 B3·§H`. 회귀 `OWN-02`, `OWN-04`, `CFL-06`.

## Q11. 경과규정의 '종전규정' 해석 — `[✅ 해결 2026-08-18, 구현 버그 수정]`

## Q8. 명세 내부 상충: 유주택 + 생애최초 처리 — `[✅ 해결 2026-08-18]`
- **결론: 상충이 아니었다.** `§E-138` 이 "처분조건부 1주택 AND 생애최초"를 **유효 조합**으로 명시하므로
  `§E-139` 의 "유주택"은 `is_owner()`(다주택 + 비처분 1주택) 의미다. 그렇다면 §E-139 는 **우선순위 규칙이
  아니라 입력 유효성 규칙**이다 — §H 는 "유효한 입력에 어떤 LTV를 주는가", §E-139 는 "그 입력이 애초에
  성립하는가"를 말한다. 층위가 다르므로 **둘 다 참**이며, §H 에 검증 게이트를 추가하면 해소된다.
- **결정: `NEEDS_HUMAN_REVIEW` (§E-139 채택).** 종전의 0% 자동판정을 폐기.
  - 0%를 자동으로 내주면 "정상 입력이고 답이 0%"와 "입력이 모순인데 우연히 0%"를 시스템이 구분하지 못한다.
  - 0%는 무해한 답이 아니라 **대출 거절**이고, 틀린 쪽이 `first_home_buyer` 플래그였다면(실제로는 무주택
    생애최초) 정답은 70%다. 0%와 70% 사이 70%p 격차가 데이터 오류 하나 뒤에 숨는 구조는 두지 않는다.
  - 이 프로젝트가 이미 두 번 적용한 원칙과 같은 부류다 — `OWNER_BASELINE_UNKNOWN`(기준값 부재),
    `UNKNOWN_REGION`(미등록 지역). **모르면 지어내지 않고 사람에게 넘긴다.**
- **게이트 위치:** P0(스코프)·P0b(정책대출) 뒤, P1(경과규정) 앞.
  스코프 밖이면 모순을 따질 필요가 없고, 모순 입력에 종전규정 70%를 주는 것도 0%만큼 위험하다.
- 구현 `src/regimpact/validation.py` · 명세 `05_RULE_SPEC §E-139 주석·§H P0c` ·
  회귀 `CFL-04`(모순), `CFL-09`(다주택+생애최초), `CFL-10`(경과규정보다 앞), `CFL-11`(정책대출이 먼저),
  `CFL-12`(처분조건부는 유효 조합 — 과잉 차단 방지).

## Q12. 다른 입력 모순도 게이트에 넣을 것인가 — `[✅ 해결 2026-08-18]`
- **결정: 스키마·논리상 명백한 3건만 채택.** 실무 여지가 있는 것은 넣지 않는다.

| 후보 | 결정 | 근거 |
|---|---|---|
| `disposal_condition_flag=True` 인데 `house_count=0` | ✅ 채택 `CONTRADICTION_DISPOSAL_WITHOUT_HOUSE` | `§A` 스키마 "처분조건부 1주택 (house_count==1과 함께)" — 처분할 주택이 없다 |
| `disposal_condition_flag=True` 인데 `house_count>=2` | ✅ 채택 `CONTRADICTION_DISPOSAL_MULTI_HOUSE` | 필드가 전제한 '1주택'이 아니다 |
| `house_count < 0` | ✅ 채택 `INVALID_HOUSE_COUNT` | 자명한 무효값 |
| `downpayment_paid_at` 만 있고 `contract_signed_at` 없음 | ❌ 미채택 | **가계약금**(정식 계약 전 계약금 선납)이 실무에 실재 |
| `downpayment_paid_at < contract_signed_at` | ❌ 미채택 | 위와 같은 현상 |

- **🔺 이전 권고 정정:** Q12 를 처음 제기할 때 "계약금만 있고 계약 없음은 데이터 결손이니 넣는 쪽이 정직하다"고
  적었으나, 다시 보니 **가계약금이라는 실무 현상이 그 두 후보(3·4번)를 같은 질문으로 묶는다.** 기계적으로 막으면
  정상 건을 사람 검토로 보낸다. 게다가 §F G2 가 "계약 체결 + 계약금 납부"를 쌍으로 요구하므로 두 경우 모두
  **경과규정이 성립하지 않을 뿐**이고 그건 이미 올바른 동작이다. → 둘 다 보류.
- **잔여:** 가계약금 인정 범위가 도메인 확인되면 3·4번을 함께 재검토한다.
- 구현 `src/regimpact/validation.py` · 회귀 `CFL-13`(보유 0채), `CFL-14`(다주택), `CFL-15`(음수),
  `CFL-16`(가계약금 — 모순 아님을 고정).
