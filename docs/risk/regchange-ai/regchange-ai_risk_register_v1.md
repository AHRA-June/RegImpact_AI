## 1. 목적·범위

본 문서는 RegChange AI의 AI/시스템 리스크를 **식별·평가·통제·모니터링**하는 리빙 레지스터다.
Model Risk / AI Governance 관점에서 각 리스크의 **고유위험(inherent) → 통제(controls) → 잔여위험
(residual)** 을 정량·정성으로 기록한다. 대상은 6·30 시나리오 기준 현행 구현이며, 상위 산출물
(`Model/System Card`, `Validation Report`, `metrics_spec`)의 근거와 정합한다.

## 2. 평가 방법론

### 2.1 척도
- **Likelihood(발생가능성) 1~5:** 1 Rare · 2 Unlikely · 3 Possible · 4 Likely · 5 Almost Certain.
- **Impact(영향) 1~5:** 1 Negligible · 2 Minor · 3 Moderate · 4 Major · 5 Severe.
  - 영향 기준(도메인): 잘못된 규제 사실·LTV 오판이 여신 의사결정·규정 준수·고객 피해로 전파되는 정도.
- **Rating = L × I**, 밴드: **Low 1–4 · Medium 5–9 · High 10–15 · Critical 16–25.**

### 2.2 통제 유형
- **[검증]** 결정론 검증(grounding·차등검증·mutation·시점 프로브·임계값 스코어카드).
- **[설계]** 아키텍처 통제(AI초안→사람확정, escalation, 결정론 분리, 스키마 강제).
- **[프로세스]** 운영 통제(버전 관리, provenance 명시, secrets 관리).
- **[계획]** 미구현·부분 통제(정식 audit, CI 게이트, 인젝션 필터).

### 2.3 원칙
- 잔여위험은 통제 후 **정직하게** 평가한다(0으로 만들지 않는다). 수용(accepted) 리스크는 근거를 남긴다.
- 고위험(★) 실패는 자동 처리 대신 사람 escalate(안전 우선).

## 4. 리스크 레지스터

> 형식: **ID · 범주 · 설명(원인→결과) · 고유(L×I=R) · 통제[유형] · 잔여(L×I=R) · 소유자 · 상태 · 모니터링/트리거.**

### 4.1 AI / 모델 리스크 (R-AI)

**R-AI-01 · LLM 환각(인용/값 날조)**
- 원인→결과: 원문에 없는 규제 수치·조건을 LLM이 생성 → 잘못된 규제 사실 전파, 여신 오판.
- 고유: L4 × I5 = **20 (Critical)**
- 통제[검증]: 인용 verbatim grounding(Citation Correctness ≥95%), Unsupported Claim Rate ≤5%,
  Source Contradiction Rate =0%(값 존재 검증). 프롬프트가 추론·창작 금지·verbatim 인용 강제.
  6·30 실측 환각 0%.
- 잔여: L2 × I4 = **8 (Medium)** — 결정론 검증이 강력하나 의미론적 모순(NLI)은 프록시로만 부분 탐지.
- 소유자: 모델검증. 상태: ✅ 통제 운영. 트리거: 스코어카드 ① FAIL 시 배포 보류·재추출.

**R-AI-02 · 예외/경과규정 누락(완전성 갭)**
- 원인→결과: 보수적 추출이 예외(생애최초·서민실수요)·경과규정을 누락 → LTV 과소/과대, 규제 전후 뒤바뀜.
- 고유: L4 × I4 = **16 (Critical)**
- 통제[검증]: 고위험 Recall 지표(Exception/Grandfathering Recall ≥95%) FAIL→종합 FAIL→escalate.
  피드백 루프 실증(1차 50% 포착 → 근거 보완 → 100%).
- 잔여: L2 × I3 = **6 (Medium)** — 검증이 포착하나 골드셋 n=1이라 미지의 예외 유형 잔존 가능.
- 소유자: 모델검증. 상태: ✅ 통제 운영. 트리거: Recall < 임계 시 사람 검토.

**R-AI-03 · 모델 버전/프롬프트 드리프트**
- 원인→결과: 기반 모델·프롬프트 변경 시 추출 동작이 조용히 바뀜 → 재현성·성능 저하.
- 고유: L3 × I3 = **9 (Medium)**
- 통제[프로세스/검증]: LLM 주입 가능(오프라인 재측정), 결정론 채점 재실행. 모델 ID는 ADJUSTABLE 명시.
- 잔여: L2 × I2 = **4 (Low)** — 단, **변경 시 자동 재측정 CI 게이트는 미구현**(수동 재실행 의존).
- 소유자: 개발/검증. 상태: ◐ 부분 통제. 트리거: 모델·프롬프트 변경 시 스코어카드 재실행 의무화(권고).

**R-AI-04 · 원문 경유 프롬프트 인젝션**
- 원인→결과: 수집 원문에 악의적 지시문 삽입 → LLM이 지시를 따라 왜곡 추출.
- 고유: L3 × I3 = **9 (Medium)**
- 통제[설계]: 원문을 `<doc id=...>` 태그로 격리, 소스 스냅샷+hash로 출처 고정, 출력은 스키마 강제.
  추출은 초안일 뿐 자동 실행 없음(영향 제한).
- 잔여: L3 × I2 = **6 (Medium)** — 전용 인젝션 필터/샌드박스는 미구현. 현재 소스는 공식 공문(신뢰).
- 소유자: 개발. 상태: ◐ 부분 통제. 트리거: 신뢰 불명 소스 추가 시 사람 사전 검수.

**R-AI-05 · 자동화 편향(사람의 형식적 승인)**
- 원인→결과: 검토자가 AI초안을 실질 검토 없이 승인 → 오류가 통제를 우회.
- 고유: L4 × I3 = **12 (High)**
- 통제[설계]: AI초안=PENDING_REVIEW 기본, escalation 세그먼트 needs_review 표기, 근거(reason_code·
  citation) 병기로 검토 부담 완화. 제안 본문 불변(감사).
- 잔여: L3 × I2 = **6 (Medium)** — 인적 요인은 완전 제거 불가. 승인 근거 기록·샘플 재검토 권고.
- 소유자: 거버넌스. 상태: ◐ 통제 운영(인적 잔여). 트리거: 승인율 이상 탐지 시 재검토.

### 4.2 데이터 리스크 (R-DAT)

**R-DAT-01 · 소스 무결성(오래된/잘못된 원문)**
- 고유: L3 × I4 = **12 (High)** · 통제[프로세스]: 스냅샷+hash 레지스터, 원본 보존.
- 잔여: L1 × I3 = **3 (Low)** · 소유자: 개발 · 상태: ✅ · 트리거: hash 불일치 시 차단.

**R-DAT-02 · PII/기밀 노출**
- 고유: L3 × I5 = **15 (High)** · 통제[설계]: 실제 회사문서·고객데이터 미사용(LOCKED §8), 공개 공문+합성만.
- 잔여: L1 × I2 = **2 (Low)** · 소유자: 거버넌스 · 상태: ✅ · 트리거: 신규 데이터 반입 시 PII 스크리닝.

**R-DAT-03 · 평가 누수(과적합)**
- 고유: L3 × I3 = **9 (Medium)** · 통제[설계]: DEV/LOCKED/CHALLENGE 분리. 룰엔진은 결정론(튜닝 루프 없음)
  → 전량 측정해도 무누수. LLM 골드셋 LOCKED/CHALLENGE 봉인.
- 잔여: L1 × I2 = **2 (Low)** · 소유자: 모델검증 · 상태: ✅ · 트리거: 튜닝 착수 시 봉인 확인.

**R-DAT-04 · 단일 앵커 일반화**
- 원인→결과: 6·30 1건 결과를 전 규제 도메인으로 확대 해석 → 성능 과대평가.
- 고유: L4 × I3 = **12 (High)** · 통제[프로세스]: n=1 명시(카드·보고서·PRD), 일반화 주장 금지.
  가짜 규제문서 생성 배제(LOCKED §8).
- 잔여: L3 × I3 = **9 (Medium, 수용)** — 실제 규제이벤트 추가 확보 전까지 잔존. **명시적 수용.**
- 소유자: 거버넌스 · 상태: ◻ 수용(disclosed) · 트리거: 신규 이벤트 확보 시 골드셋 확대.

### 4.3 룰/의사결정 리스크 (R-RUL)

**R-RUL-01 · 룰엔진↔명세 불일치(구현 버그)**
- 고유: L3 × I5 = **15 (High)** · 통제[검증]: 독립 오라클 차등검증(격자 3,200 전량 100%) + mutation
  방어력 + seed/큐레이션 3계층.
- 잔여: L1 × I2 = **2 (Low)** · 소유자: 개발/검증 · 상태: ✅ · 트리거: 회귀 < 100% 시 배포 차단.

**R-RUL-02 · 명세 공백(비규제 유주택 기준선 부재)**
- 고유: L3 × I3 = **9 (Medium)** · 통제[설계]: 임의값 대신 NEEDS_HUMAN_REVIEW escalate, 영향 매트릭스에 노출.
- 잔여: L2 × I2 = **4 (Low)** · 소유자: 도메인 · 상태: ◐ Q6 확정 대기 · 트리거: 규제사실 검수로 값 확정.

**R-RUL-03 · 시점 오적용(시행일/버전)**
- 고유: L3 × I4 = **12 (High)** · 통제[검증]: 지역 시점 버전 데이터 + Policy-version Consistency 프로브
  (효력일 경계 12/12), Effective-date =100%.
- 잔여: L1 × I2 = **2 (Low)** · 소유자: 개발/검증 · 상태: ✅ · 트리거: 시점 지표 < 100% 시 차단.

**R-RUL-04 · 명세 내부 상충(유주택+생애최초, Q8)**
- 원인→결과: §E(escalation)와 §H(P4 0%) 상충 → 모순 입력의 판정 불확실.
- 고유: L3 × I3 = **9 (Medium)** · 통제[검증/설계]: §H를 권위 기준으로 채택, ConflictCase spec_note로 표면화,
  Q8로 문서화. 엔진·오라클 일치.
- 잔여: L3 × I3 = **9 (Medium, 수용)** — 도메인 확정 전까지 모호성 잔존. 명시적 수용.
- 소유자: 도메인 · 상태: ◻ 수용(Q8) · 트리거: 도메인 확정 시 엔진·오라클·회귀 동시 갱신.

### 4.4 프로세스/거버넌스 리스크 (R-GOV)

**R-GOV-01 · 정식 감사추적 부재**
- 원인→결과: append-only audit log 미구현 → 사후 추적·책임소재 확인 제약.
- 고유: L4 × I3 = **12 (High)** · 통제[설계/프로세스]: approval 기록(status·검토자·시점, 본문 불변),
  소스 hash, 결정론 재현으로 **부분 대체**.
- 잔여: L2 × I3 = **6 (Medium)** · 소유자: 거버넌스 · 상태: ⬜ 계획 · 트리거: 정식 audit logger 구현.

**R-GOV-02 · Human Review 우회/무단 변경**
- 고유: L3 × I4 = **12 (High)** · 통제[설계]: 제안 본문 불변(record_decision은 새 객체), approval envelope
  필수, 규칙값은 LLM이 생성 불가(LOCKED §4).
- 잔여: L2 × I3 = **6 (Medium)** · 소유자: 거버넌스 · 상태: ◐ · 트리거: 승인 없는 변경 감지 시 롤백.

**R-GOV-03 · 임계값 오보정(Threshold miscalibration)**
- 원인→결과: 너무 관대 → 고위험 miss; 너무 엄격 → 경보 피로(alert fatigue).
- 고유: L3 × I3 = **9 (Medium)** · 통제[프로세스]: Strict 프로파일 사용자 확정, 단일 진실 코드화
  (thresholds.py), 근거 문서화(metrics_spec §0-C, DECISION_LOG), 고위험 태깅.
- 잔여: L3 × I2 = **6 (Medium)** — 임계값은 내부 판단(제3자 검증 아님). 주기적 재검토 필요.
- 소유자: 모델검증 · 상태: ◐ 확정·리뷰 대상 · 트리거: FAIL/WARN 추세·도메인 피드백 시 재보정.

### 4.5 운영 리스크 (R-OPS)

**R-OPS-01 · 재현 불가**
- 고유: L2 × I3 = **6 (Medium)** · 통제[검증]: 결정론 파이프라인(난수 없음), 안정 case_id, 테스트 110개,
  재현 명령 문서화.
- 잔여: L1 × I2 = **2 (Low)** · 소유자: 개발 · 상태: ✅ · 트리거: 재현 실패 시 원인분석.

**R-OPS-02 · 시크릿 노출(API 키)**
- 고유: L3 × I4 = **12 (High)** · 통제[프로세스]: 환경변수(`ANTHROPIC_API_KEY`), `.gitignore`, 저장소 미커밋.
- 잔여: L2 × I1 = **2 (Low)** · 소유자: 개발 · 상태: ✅ · 트리거: 시크릿 스캔 경보.

**R-OPS-03 · Provenance 모호(수동 vs 자동 실행)**
- 원인→결과: 추출이 수동 grounded인지 자동 API인지 불분명 → 결과 해석 오도.
- 고유: L3 × I2 = **6 (Medium)** · 통제[프로세스]: 산출물 `_meta.provenance` 명시, 카드·보고서에 반복 고지.
- 잔여: L1 × I2 = **2 (Low)** · 소유자: 거버넌스 · 상태: ✅ · 트리거: 자동 API 실행 시 provenance 갱신.
