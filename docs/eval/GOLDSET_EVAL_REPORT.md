## 2. ⚠️ 첫 채점은 틀렸다 — 모델이 아니라 채점기가 문제였다

최초 실행에서 12건이 "골드 사실 누락"으로 잡혔다. 튜닝에 들어가기 전에 답변 원문을 하나씩
열어 본 결과 **12건 전부 내용이 맞았고, 전부 표현 차이였다.**

| 골드 앵커 | 모델 답변 | 실제 |
|---|---|---|
| `25.9.7` | "2025년 9월 7일부터 시행" | 같은 날짜, 표기만 다름 |
| `증액 없는 대환대출` | "증액없는 대환대출" | 띄어쓰기 |
| `취급시점` | "취급한 시점" | 조사 |
| `旣 마련된 규정` | "이미 마련되어 있던 규정" | 같은 뜻 |
| `규제지역 여부와 무관` | "규제지역인지 여부와 관계없이" | 같은 뜻 |
| `非규제지역은 해당 없` | "非규제지역(수도권 외)은 해당없음" | 괄호 삽입 |

여기서 프롬프트를 손봤다면 **채점기에 맞춰 모델을 훈련시킨 것**이 된다. 그래서 모델이 아니라
채점기를 고쳤다:

1. **표면 정규화** — 공백 전부 제거, 날짜 표기 통일(`2025년 9월 7일` → `25.9.7`), 따옴표·중점 통일.
   의미를 바꾸지 않는 차이만 제거한다.
2. **`|` 동의 표현** — 골드 파일에 명시해 사람이 감사할 수 있게 한다. **모델이 실제로 같은 내용을
   말한 경우에만** 추가했고, 그 판단 근거로 답변 원문을 함께 확인했다.
3. LLM 심판은 쓰지 않는다 — 채점의 신뢰도를 다시 검증해야 하는 회귀가 시작된다.

채점기를 느슨하게 만드는 것은 지표를 망가뜨리는 가장 흔한 경로이므로, `tests/test_qa_eval.py`가
**양방향**으로 고정한다: 표면 차이는 통과해야 하고(6건), 내용 차이는 여전히 실패해야 한다(4건).

### 같은 오차가 Extractor 지표도 오염시키고 있었다
이 원인(PDF 추출본이 단어 중간에서 줄바꿈)을 확인한 뒤 기존 Extractor 실행을 재채점하니,

## 4. 아직 측정되지 않은 것 (정직한 한계)

- **D-02(서민·실수요자 누락)는 이 평가에서 재현되지 않았다.** DEV-EXC-002가 세 대상을 모두
  물었을 때 모델은 전부 답했다. D-02는 "문서 전체를 한 번에 구조화 추출"할 때 나타나는 실패이고,
  QA는 질문이 대상을 지목해 준다. **두 태스크는 난이도가 다르다** — QA 95%가 추출기의
  Exception Recall 50%를 반증하지 않는다. 두 지표를 섞어 보고하지 않는다.
- **batch_size=5의 오염 가능성.** 한 배치 안의 질문끼리 서로 힌트가 될 수 있다. 비용 때문에
  묶었으며, 이 값을 실행 기록에 함께 남긴다. 배치 크기별 민감도는 미측정.
- **골드셋은 전 문항 🤖 초안** — 사람 도메인 검수 전이다. 상대 비교(before/after)에는 쓸 수 있으나
  절대 수치는 검수 후 재확인해야 한다.
- **LOCKED/CHALLENGE 미실행.** 봉인 유지 중이며, 이 리포트의 수치는 DEV 기준이므로
  최종 성능이 아니다.
